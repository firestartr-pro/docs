# Contributing to Firestartr Documentation

This guide explains how to contribute to the Firestartr documentation and test your changes locally.

## Documentation Structure

The documentation is organized as follows:

```
docs/
├── site/
│   ├── homepage/               # DESTINATION-OWNED homepage source
│   │   ├── _index.md           # Homepage content (editorial, English)
│   │   └── images/             # Homepage image assets
│   ├── raw/                    # SOURCE - promoted from other repositories
│   │   ├── core/               # Core Firestartr documentation
│   │   │   ├── docs/           # Deployment guides, providers/, and backstage/
│   │   │   ├── crds/           # Custom Resource Definitions (versioned)
│   │   │   └── claims/         # Claims JSON schema
│   │   ├── features/           # Individual feature documentation
│   │   └── images/             # Promoted images
│   └── web/                    # Hugo static site
│       ├── hugo.toml           # Hextra and Hugo configuration
│       ├── go.mod / go.sum     # Pinned Hextra Hugo Module
│       └── layouts/            # Small local render-hook overrides
├── scripts/
│   └── migrate-content.sh      # Single migration used by CI, local preview, and tests
└── .github/workflows/
    └── deploy-docs.yml         # Automated deployment workflow
```

`site/web/content/`, `site/web/static/`, and `site/web/public/` are generated by the
migration and are not tracked.

## Editing Documentation

### Where to Edit

- **Homepage**: edit `site/homepage/_index.md` and its images under `site/homepage/images/`.
  The homepage is destination-owned editorial content: a promotion of
  `site/raw/core/docs/README.md` (or any other promoted file) must never replace it.
- **Deployment guides**: edit files in `site/raw/core/docs/`.
- **Providers**: edit files in `site/raw/core/docs/providers/`.
- **Feature documentation**: edit files in `site/raw/features/<feature-name>/`.

Never edit files under `site/web/content/`, `site/web/static/`, or `site/web/public/` -
they are generated by the migration script.

### Documentation Workflow

1. Edit the source files (or `site/homepage/` for the homepage).
2. Run the migration locally: `bash scripts/migrate-content.sh`.
3. Preview with Hugo (see below).
4. Commit the change on a branch and open a pull request.
5. After the pull request is merged to `main`, GitHub Actions runs the same migration,
   builds, tests, and deploys.

## Testing Documentation Locally

### Prerequisites

Install Hugo extended 0.152.2 and Go:

```bash
# macOS (Homebrew)
brew install hugo

# Linux (Snap)
snap install hugo

# Or download from https://github.com/gohugoio/hugo/releases
```

Verify installation:

```bash
hugo version
# Should show v0.152.2 with "extended"
go version
```

### Download the Hextra Module

Hextra is pinned in `site/web/go.mod`. Fetch that exact module version before the first
local build:

```bash
cd site/web
go mod download
cd ../..
```

### Migrate and Preview

Use the same script CI uses, so local output matches the deployed site:

```bash
bash scripts/migrate-content.sh
cd site/web
hugo server
```

The documentation site will be available at **http://localhost:1313/docs/**.

Hugo watches `site/web/content/` and rebuilds on changes there. If you edit files in
`site/raw/` or `site/homepage/`, re-run `bash scripts/migrate-content.sh` (the script is
safe to run repeatedly).

### Optional Ephemeral Preview Tunnel

To open the local preview from another device, use a Cloudflare quick tunnel. Start the
Hugo server as above, then run this in another terminal:

```bash
cloudflared tunnel --url http://localhost:1313
```

Copy the ephemeral `https://<random>.trycloudflare.com` URL from its output. Restart Hugo
with that origin as its base URL so generated links continue to include the `/docs/`
prefix without pointing at production:

```bash
cd site/web
hugo server --port 1313 \
  --baseURL 'https://<random>.trycloudflare.com/docs/' \
  --appendPort=false
```

This is a quick tunnel only: do not create a named tunnel, commit the ephemeral URL, or
add the tunnel to CI.

### Quick Build (Without Server)

To build the static site without running a server:

```bash
bash scripts/migrate-content.sh
cd site/web
hugo --minify
```

Output will be in `site/web/public/`.

## Testing GitHub Actions Build Artifacts

If you want to test the documentation site generated by the GitHub Actions workflow without setting up Hugo locally:

### Step 1: Download the Artifact

1. Go to the `Actions` tab in the repository
2. Click on the workflow run you want to test
3. Scroll down to the "Artifacts" section
4. Download the artifact
5. Extract the downloaded ZIP file

### Step 2: Serve the Static Site

Navigate to the extracted `public` directory and start a local web server:

```bash
cd public
python3 -m http.server 8000
```

### Step 3: View the Site

Open your browser and navigate to **http://localhost:8000/**

You can now browse the documentation site exactly as it will appear after deployment.

## Migration Rules

`scripts/migrate-content.sh` follows these rules.

### Homepage (`site/homepage/`)
- `_index.md` → `site/web/content/_index.md`, with its front matter preserved.
- Promotions never write `site/web/content/_index.md`.

### Deployment guides (`site/raw/core/docs/`)
- `README.md` → `content/deploying-resources/_index.md` with the title, weight, main-menu
  membership, and a `cascade` that sets `type = 'docs'` for the section.
- Every other `.md` file except the `providers/` and `backstage/` subtrees → copied
  under `content/deploying-resources/` with front matter `weight = 1`.

### Providers (`site/raw/core/docs/providers/`)
- `README.md` → `content/providers/_index.md` with `title = 'Providers'`, `weight = 2`,
  main-menu membership, and a `cascade` that sets `type = 'docs'`.
- Nested `README.md` files → the directory's `_index.md` with `weight = 1`.
- Other `.md` files → copied with front matter `weight = 1`.

### Features (`site/raw/features/`)
- `README.md` → `content/features/_index.md` with `title = 'Features'`, `weight = 3`,
  main-menu membership, and a `cascade` that sets `type = 'docs'`.
- Feature `README.md` → `content/features/<name>/_index.md` with `weight = 1`.
- `CHANGELOG.md` → copied as-is (no front matter).
- Other `.md` files → copied with front matter `weight = 1`.

### Firestartr Portal (`site/raw/core/docs/backstage/`)
- Optional: the section is published only when the Backstage-owned subtree is present
  (promoted from `prefapp-backstage`).
- `README.md` → `content/backstage/_index.md` with `title = 'Firestartr Portal'`,
  `weight = 4`, main-menu membership, and a `cascade` that sets `type = 'docs'`.
- Nested `README.md` files → the directory's `_index.md` with `weight = 1`.
- Other `.md` files → copied with front matter `weight = 1`.

### Static Assets
- `logos/logo.png` → `site/web/static/favicon.png` and
  `site/web/static/images/logo.png`.
- `site/raw/images/` and `site/homepage/images/` → `site/web/static/images/`.

### Link Rewrites
- Links ending in `/README.md` → their directory index (`/`).
- Relative Markdown page links → directory-style page URLs.
- Relative `./images/...` references → root-absolute `/images/...` references, which
  publish beneath `/docs/images/...` because of the configured base URL.
- GitHub feature repository links → published `/features/<feature>/...` pages.

## Hugo Configuration

The Hugo configuration is in `site/web/hugo.toml`:

- **Theme**: Hextra, consumed as a Hugo Module pinned in `go.mod`
- **Base URL**: `https://docs.firestartr.dev/docs/`
- **Search**: Offline FlexSearch in the navbar
- **Theme mode**: Light by default, with a navbar toggle
- **Documentation layout**: Applied by each published area's generated front-matter
  cascade; the destination-owned homepage keeps Hextra's default article layout

## Deployment

When you push to the `main` branch, GitHub Actions automatically:

1. Runs `scripts/migrate-content.sh`
2. Builds the Hugo site with minification
3. Deploys to the `gh-pages` branch
4. GitHub Pages serves the site from the `gh-pages` branch

## Common Issues

### Theme Module Not Found

If Hextra cannot be resolved, verify that Go is installed and fetch the pinned module:

```bash
cd site/web
go mod download
```

### Links Not Working

Run `python3 scripts/test-generated-site.py`; it rebuilds the site and checks internal
page, image, and anchor targets.

### Images Not Displaying

Promoted images belong in `site/raw/images/`; homepage images belong in
`site/homepage/images/`. Reference them relatively from markdown:

```markdown
![Alt text](./images/filename.png)
```

The migration copies both locations into `site/web/static/images/` and rewrites those
references to `/images/...`.

## Style Guidelines

- Use clear, concise language
- Include code examples where appropriate
- Use proper markdown formatting
- Document all configuration options
- Provide troubleshooting sections for complex features
- Link to external resources when helpful
